## Overview

DocuMind is a retrieval-augmented Q&A engine for large document collections. You upload documents, it chunks and embeds them, and then answers questions against the corpus with the retrieved passages behind every answer.

## The problem

An LLM asked about documents it has never seen will answer anyway. The fix is not a better prompt — it is making sure the model only ever sees text that actually exists in the corpus, and making the retrieval step good enough that the right text is in the window.

## Architecture

The API surface splits into three: documents, query, and conversations. Behind them sits a service layer with two halves.

The **document processor** handles ingestion — parsing, chunking, and handing chunks to the embedding service, which writes vectors into `doc_chunks` in PostgreSQL via pgvector.

The **RAG pipeline** handles reads: vector search over those chunks, a memory service that carries conversation state across turns, and GPT-4o for synthesis. Answers stream back over SSE, so tokens land as they are produced rather than after the full generation.

Nginx sits in front as a reverse proxy. Postgres holds `documents`, `doc_chunks` and `conversations` + `messages` in one database, so a conversation and the chunks it cited stay joinable.

## Wins

- Conversation memory means follow-up questions resolve against earlier turns instead of starting cold.
- Streaming over SSE removes the dead wait between question and first token.
- One Postgres instance for both relational data and vectors — no separate vector database to operate.
