## Overview

Documind answers questions against a private document corpus — 50,000+ indexed pages — and shows its work. Every answer carries the passages it was built from, so a wrong answer is diagnosable instead of mysterious.

## The problem

A single-shot RAG pipeline retrieves once and hopes the top-k chunks contain the answer. For anything that spans documents — "which of these contracts renew before Q3, and what changed in each?" — one retrieval pass is not enough, and the model fills the gap by inventing.

## Approach

The pipeline is a LangGraph state machine rather than a chain. A planner decides whether the question needs decomposition; each sub-question runs its own retrieval against pgvector; a grader scores the retrieved passages and can send the graph back for another pass before synthesis is allowed to start.

Answers stream out of FastAPI over server-sent events, so the first tokens land while later sub-questions are still resolving.

## Wins

- **40% fewer hallucinations** against a held-out question set, measured by manual grading of cited-vs-claimed spans.
- 99.5% uptime across the deployment window on a single AWS EC2 instance behind Docker.
- Retrieval grading catches empty-context cases and returns "not in the corpus" instead of guessing.
