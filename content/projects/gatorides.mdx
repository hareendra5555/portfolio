## Overview

A ride-sharing platform for urban commutes, built by a four-person team as a software engineering project at UF. Riders post where they need to be picked up, drivers advertise availability, and the same account can do both.

**My role: backend.** I worked on the Go services with Shahid Shareef Mohammad, while Dhanush Kumar Reddy Gujjula and Venkata Sandeep Macha built the frontend.

## The problem

The interesting constraint is that there is no fixed role. A user is a rider on Monday and a driver on Tuesday, so the data model cannot hang permissions off an account type — it has to treat rider and driver as things an account *does*, not things it *is*.

Matching is the other half: finding drivers heading roughly the same way as a rider, close enough to be worth the detour.

## What the backend does

Auth and session handling, the ride lifecycle — request, match, accept, complete — the route-matching logic that pairs riders with drivers on compatible routes, and the ratings API that both sides write to after a trip.

Controllers are covered by table-driven tests under `tests/controllers`, run with `go test ./tests/controllers -v`.

## Notes

The goal behind the project was congestion and commute cost — fewer single-occupancy cars making the same trip. Mutual participation is what makes that work: a platform where drivers are also riders has a much better chance of route overlap than one with two separate populations.
